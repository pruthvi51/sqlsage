## 1. Executive Overview & Problem Statement

Deploying general-purpose Large Language Models (LLMs) for enterprise Text-to-SQL over complex relational schemas suffers from three catastrophic failure modes:
1. **Entity and Column Hallucination:** In massive enterprise schemas containing hundreds of attributes, general-purpose LLMs frequently invent non-existent column names (e.g., querying `patient.diabetes_flag` instead of joining `conditions` on ICD-10 code `'E11.9'`), resulting in immediate runtime failures.
2. **Context Window Saturation & Noise:** Providing entire enterprise database catalogs inside LLM prompts incurs prohibitive token overhead ($> 4,500$ tokens per prompt) and introduces distracting schema noise that degrades semantic retrieval accuracy.
3. **Silent Semantic Execution Failures:** Syntactically valid SQL generated by LLMs frequently fails at execution time due to missing `GROUP BY` expressions, ambiguous column references, or unjoined Cartesian products.

**SQLSage eliminates these failure modes** through a formal four-stage translation pipeline that combines graph theory, constrained grammar decoding, and sandboxed test execution.

## 3. Key Technical Innovations

### MinHash LSH Value & Entity Indexing
Clinical terminology frequently exhibits colloquial synonyms (e.g., *"sugar sickness"* $\to$ Type 2 Diabetes `E11.9`, *"high BP"* $\to$ Essential Hypertension `I10`). SQLSage indexes clinical vocabularies using MinHash Locality-Sensitive Hashing (LSH), mapping free-form tokens to canonical database entities with sub-millisecond lookup times.

### NetworkX Steiner Tree Schema Pruning
Rather than feeding sprawling schemas into prompt contexts, SQLSage models foreign-key relationships as a weighted multigraph $G = (V_T \cup V_C, E)$. It computes the minimum Steiner tree connecting the matched seed tables:
$$T^* = \arg\min_{T \subseteq G} \sum_{e \in E(T)} w(e) \quad \text{s.t. } S \subseteq V(T)$$
This guarantees that intermediate join bridge tables (e.g., joining `patients` to `claims` via `encounters`) are automatically included while eliminating dozens of irrelevant tables.

### Schema-Guided Constrained Decoding (SGCD)
SQLSage enforces lexical and relational grammar constraints via AST transitions:
$$M_t(w) = \begin{cases} 1 & \text{if } \text{ValidTransition}(\mathbf{y}_{<t} \circ w, \mathcal{G}_{\text{SQL}}) \land \text{ValidEntity}(\mathbf{y}_{<t} \circ w, V^*) \\ 0 & \text{otherwise} \end{cases}$$
This mathematical guarantee precludes the engine from generating hallucinated column references or invalid syntax.

### Ephemeral DuckDB Sandbox Self-Correction
Before returning SQL to clinical practitioners, SQLSage test-executes the candidate query against an isolated DuckDB sandbox initialized with synthetic schema tables. Runtime errors trigger progressive AST repair heuristics:
* **Missing GROUP BY:** Automatically identifies unaggregated projection expressions and appends the appropriate `GROUP BY` clause.
* **Misqualified Table Prefixes:** Automatically resolves table qualification conflicts.

## 4. CareLake-QA Benchmark Suite (150 Queries)

SQLSage is evaluated on **CareLake-QA**, an enterprise clinical Text-to-SQL evaluation dataset comprising **150 curated queries** across the CareLake dimensional lakehouse:

| Complexity Tier | Query Count | Characteristics & Target SQL Features |
| :--- | :--- | :--- |
| **Easy** | 50 Queries (IDs 1–50) | Single-table aggregations (`COUNT`, `SUM`, `AVG`), basic filtering, distinct counts. |
| **Medium** | 50 Queries (IDs 51–100) | Multi-predicate filtering, categorical `GROUP BY`, date ranges, `ORDER BY` / `LIMIT`. |
| **Hard** | 50 Queries (IDs 101–150) | Multi-table joins (`patients` $\times$ `encounters` $\times$ `conditions`), 30-day readmissions, window functions (`SUM OVER PARTITION`), subqueries. |

## 6. Quickstart Guide

### 1. Installation
```bash
git clone https://github.com/pruthvi51/sqlsage.git
cd sqlsage
make setup
```

### 2. Run Test Suite & Evaluation Benchmark
```bash
make test
make bench
```

### 3. Translate Natural Language via CLI
```bash
# Check platform status and benchmark active count
sqlsage status

# Translate natural language question
sqlsage translate "What is the average length of stay in hours for emergency admissions?"

# Compute Steiner tree join path connecting disjoint tables
sqlsage graph --tables encounters,conditions
```

### 4. Launch Interactive Streamlit Workbench
```bash
make demo
```
Navigate to `http://localhost:8501` to explore:
* **Interactive NL-to-SQL Translator:** End-to-end 4-stage pipeline execution traces.
* **CareLake-QA Benchmark Explorer:** Browse all 150 curated queries by complexity tier.
* **Relational Schema Graph:** Compute Steiner tree subgraphs between arbitrary tables.
